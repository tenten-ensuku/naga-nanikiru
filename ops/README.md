# Ensuku Ops v2 — 日次・容量確認専用

目的は無料枠の使用率・残量・節約候補を一元表示すること。監視自身が負荷源にならないよう、2026-09-07に詳細な自動制御計画から簡素化した。

## 定常運転

- `wrangler.ops.jsonc`のCronは `0 18 * * *`（毎日03:00 JST）の1本だけ。
- 同じJST日に複数のイベントが届いても、永続的な日付ロックで追加取得しない。失敗後もその日の自動再試行はしない。
- Supabaseは2DBの集計・画像参照キー・既存画像予算の更新、合計4回/日。本文・画像そのもの・利用者情報はダウンロードしない。
- R2は対象2バケットの一覧メタデータのみ。画像本体GET・新規コピーは0件。
- Cloudflare Analyticsの読み取り専用トークンが設定された場合のみ、利用回数を1回/日取得。未設定や失敗は「不明」。認証のためのCLI OAuthをWorkerへコピーしない。
- 管理画面は保存済みの`state.json`と`history.json`だけを読む。自動ポーリング・画面表示時の本番集計なし。
- 履歴は1日1行、最大90日を小さなJSON1つに保存。旧15分履歴は2日後、旧日次ファイルは90日後に管理バケット内の対象だけ期限整理する。
- Supabase EgressはDashboardで確認した期間値を手動登録。確認日時を常に表示し、7日以上前は前回値扱い。期間外は不明。API回数をEgressに換算しない。

## 管理自身の負荷

`overhead`は既に必要だった集計レスポンスのUTF-8ペイロードサイズ・HTTP回数・R2一覧回数を測る。測定のための追加通信はしない。HTTPヘッダー・圧縮・Supabase内部の転送や管理画面配信等は含まないため、公式の請求Egressと同一視しない。30倍した月間値は「推計」。管理バケットの保存量はR2の管理用データとして日次集計に含める。

## 制限とアクセス

- `READ_ONLY_MODE=true`は`CONTROL_SYNC_ENABLED`や`ENFORCEMENT_READY`より優先する。アプリの停止・再開RPCを呼ばず、`/api/resume`も拒否する。
- 既存DBの`private.ops_capacity_control`は`armed=false, blocked=false`。このモードを終了するだけで自動制御を再開しない。再導入は別途設計・承認・試験を必要とする。
- 画像配信Workerに元々ある8GB予約予算は維持する。閲覧・回答保存をこのダッシュボードの判断では停止しない。
- Cloudflare Accessは管理Worker `ensuku-ops` のみ、本人のメール一致ルール1本。他のアプリ・画像Workerを対象にしない。
- Worker側でもAccess JWTの署名・期限・AUD・本人メールを検証する。メール・Botトークン・監視トークンはWorker Secretsに保存。
- 新しい通知DMは無効。接続確認DMはv1で送信済み。日次の静かな容量確認を優先する。
- Sites・D1移行・画像削除・回答履歴削除・料金契約変更は行わない。

## 検証と復旧

`npm run test:ops`、`node scripts/qa-ops.mjs`（ローカルfixtureのみ）を実行する。公開後は`node scripts/ops-verify-live.mjs public`で未認証拒否を確認し、本人ログインで表示・HTML保存を確認する。

日次実行が失敗した場合は前回値と取得日時を残す。画面の故障を理由に学習アプリを停止しない。必要なら管理Workerだけをロールバックし、Cronを無効にして静的HTMLを参照する。保存量・期間平均・通信量は別指標であり、無停止・完全無課金を保証するものではない。
